Design system — Local LLM Bench

Source de vérité du style pour le dashboard : tokens (mapper 1:1 dans Tailwind), composants réutilisables (cards, tables, filtres, badges, graphiques, états) et maquettes des trois vues — liste des runs, détail d'un run, comparaison multi-runs — en desktop et mobile. Les valeurs des maquettes sont des exemples, jamais des données réelles.

Accessibilité : contraste AA (4.5:1 texte normal), focus visible partout, aria-* sur les contrôles, graphiques en SVG avec role="img" + aria-label, tables avec scope, thème sombre persisté en localStorage.

1 · Design tokens

Définis en CSS custom properties en haut du fichier (bloc :root). Côté app, mapper chaque token dans tailwind.config : couleurs → theme.colors, espacements → spacing, radius/ombres → borderRadius/boxShadow. Le thème sombre ne change que les valeurs des tokens — zéro code à part [data-theme="dark"].

2.9 Graphiques (SVG natif — zéro lib)

Principe : les graphiques sont dessinés en SVG inline par l'app (pas de dépendance chart). La règle visuelle est fixée ici : barres arrondies --r-sm, 1 couleur de --ch-* par run, axe Y discret, libellés en mono 11 px, grille = --c-border. Chaque SVG porte role="img" + aria-label.

Design system — Local LLM Bench. Un seul fichier, zéro dépendance, zéro build — ouvert dans n'importe quel navigateur. Les tokens sont la source de vérité : à re-mapper dans Tailwind côté app. Les maquettes sont statiques (valeurs d'exemple).

Accessibilité : contraste AA, focus visible, aria-*, graphiques role="img". Thème sombre via le switch (persisté). Responsive : mobile-first, tableaux → cartes sous 768 px.
